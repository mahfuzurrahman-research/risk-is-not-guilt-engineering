## Supported repository wording

Built a synthetic advertising-integrity risk workflow with logistic-regression/random-forest comparison, Isolation Forest anomaly scoring, availability-aware temporal holdouts, and a capacity-bounded, label-free investigation queue; validated scoring-policy persistence and failure handling through automated tests; added GitHub Actions and Docker execution paths.

Docker reproducibility may be included once the container build and execution checks on this commit are successful. The workflow contains those checks; their presence alone is not execution evidence.

## Claim limits

This supports hands-on Python/scikit-learn classification, anomaly scoring, temporal validation, queue prioritization, and testing experience on fabricated data.

It does not support commercial fraud-detection performance, production deployment, employment on Google Ads, real-world fraud labels, a calibrated fraud probability, or improved scientific identification in the private paper.

Do not quote synthetic AP/AUC as real fraud-detection performance. The anomaly mixture does not improve queue precision over classifier-only ranking in the recorded default run.

This supports domain-specific investigation engineering on controlled fixtures. It does not establish real Google Ads fraud reduction, policy enforcement, confirmed actor tracking, malware reverse engineering or live incident response. Public-feed adapters do not mean public threat data was used in the default benchmark. Test counts and observed hosted execution are documented in `ads_validation_record.md`.
